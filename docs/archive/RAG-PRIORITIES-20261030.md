RAG는 검증 전 기본 비활성을 유지한다. 아래는 RAG 작업 내부의 선후 관계이며 기존 전시 일정을 대체하지 않는다.

### 평가·구현 조건

- [ ] 정답셋은 자연어 질문만이 아니라 **실제 스냅샷에서 생성한 검색 질의**를 중심으로 만든다.
  공통 개념, 단기 이벤트의 조건·한계, 장기 연구의 단기 오용 반례, 미래·철회·만료·타 종목 자료 제외 사례를 포함한다.
  위 자료 수는 초기 목표이며 검수 품질을 우선한다.
- [ ] 현재 BM25 → 한국어 보강 BM25 → 필요할 때만 하이브리드 검색 순으로 비교한다.
  벡터 DB·임베딩·재순위화 도입 자체를 완료 목표로 삼지 않는다.
- [ ] 검색 방식이 바뀌어도 검수·시장·종목·공개/관측 시점·유효 기간 필터와 원문 무결성 검사를 유지한다.
  검색 버전·질의·선정/제외 사유·고정 컨텍스트를 저장하고 기존 실행 재생을 보존한다.
- [ ] 현재 UTF-8 바이트 기반 2,000 상한을 실제 선택 모델의 토큰 측정과 비교한다.
  길이 때문에 제외되는 비율을 기록하고, 사전 문단 분할 시 원문 위치·적용 조건·한계를 보존한다.
  제한을 늘리기 전에 전체 입력 예산과 비용 영향을 확인한다.
- [ ] 동일 스냅샷·모델·선공 조건에서 RAG 없음/현재 BM25/개선 검색을 비교한다.
  반복 실행과 사람 검토를 포함하고 검색 품질 향상과 토론 품질 향상을 별도로 판정한다.
  유료 실행 전 모델·반복 수·호출/비용 상한과 운영 허용 기준을 확정한다.
- [ ] 실패 정책 변경안: 자료 없음·일시적 검색 시간 초과는 RAG 없이 진행한 사실을 기록하고,
  무결성 오류·시점 위반·감사 저장 실패는 중단한다. 현재 구현과 구분하며 오류 유형 분류와 회귀 테스트 후 적용한다.

- [ ] 실제 Spring/DB·시장 공급자·운영 설정으로 연결 검증 후 제한적으로 활성화한다.
  7거래일 성숙 결과로 예측 성과를 별도 평가하고 3거래일은 보조로 유지한다.
