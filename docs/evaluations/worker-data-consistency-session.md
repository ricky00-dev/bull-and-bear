## 확인한 결함과 수정

- CLI `build_snapshot`은 장중 일봉을 경고만 붙여 사용했다. HTTP와 같은 KST 15:40 cutoff를
  공유하고 공급자가 범위를 어겨도 당일 미확정·미래·조회 범위 밖 행을 제거한다.
  timezone 없는 관측 시각은 머신 로컬 시간으로 추정하지 않고 거부한다.
  일봉 OHLC/유한값 검증도 추가했다.
- `VAL.SHARES.as_of`가 종가 날짜로 덮여 공시가 최신인 것처럼 보였다.
  공급자의 주식수 공시일을 보존하며 시가총액 등 계산값은 가격 기준일을 유지한다.
  미래 공시·보고서·주식수를 제외하고 뉴스는 공급자가 필터를 어겨도 생성 cutoff 이후를 제외한다.
- 기존 KRX 캐시는 날짜만 검사했다. NaN 가격 같은 형식 오류가 있는 과거 비어 있지 않은 캐시는
  영구 재사용될 수 있었다. 읽기·저장 전 OHLC, 수량, 지수와 기준 지수 존재를 검사한다.
  손상/잘린 gzip도 재조회 대상이다. 유효하지 않은 새 응답은 저장하지 않는다.
- 장 마감 전 생성된 캐시가 시간이 지나 과거 확정 종가로 재사용되는 경로를 막았다.
  mtime이 해당 날짜 15:40 이전이면 재조회한다. 빈 응답 TTL은 1시간에서 60초로 줄여
  휴장과 아직 미발표인 응답을 같게 영구 취급하지 않는다. 정상 최근 응답 1시간,
  7일보다 오래된 정상 비어 있지 않은 응답의 장기 재사용 정책은 유지했다.

## 코스피 비교 보완

스냅샷에 선택적 지수 loader를 연결했다. 최근 최대 22개 종목 거래일 구간만 조회하고,
3·7·21종목 거래일 전과 가격 기준일의 **양 끝 날짜가 정확히 같은 경우에만** 다음 Fact를 생성한다.

- `PX.RET_{3,7,21}D`: 종목 과거 수익률.
- `MKT.KOSPI_RET_{3,7,21}D`: 동일 날짜 사이 코스피 수익률.
- `PX.EXCESS_KOSPI_{3,7,21}D`: 반올림 전 두 수익률의 차이, %p.

기존 `category=price`, `unit=%`를 유지하고 초과수익률의 %p 의미는 label에 명시한다.
note에 시작·종료 날짜와 종목/지수 원시 종가를 남기고 파생 Fact의 inputs를 연결한다.
지수 날짜 누락·상충 중복·비유한값·공급자 실패는 비교값을 만들지 않고 경고한다.
지수 실패로 종목 스냅샷 전체를 중단하거나 날짜를 앞뒤로 보간하지 않는다.
`Market.snapshot`도 일별 지수 endpoint와 같은 loader를 사용하며 종목 quote는 계속 고정한다.
공개 HTTP 필드/계약, 공통 schemas/config, service/store, 프롬프트/검증기는 변경하지 않았다.

이것은 **과거 비교 근거**다. 미래 3·7거래일 상대성과의 정답이나 예측 품질 검증이 아니다.
거래정지로 종목 날짜가 건너뛰면 종목 거래일 수와 시장 거래일 수가 달라질 수 있어 label에도
종목 거래일임을 적었다. 기업행사는 감지·보정하지 않고 원시 종가 미보정을 note에 명시한다.

## 한계와 범위 밖 제안

1. `Snapshot.as_of`는 가격 날짜, `created_at`은 조회 시작 때 고정한 정보 cutoff다.
   개별 공급자의 실제 fetched_at/observed_at을 저장하지 않으며 역사적 vintage를 증명하지 않는다.
   재무·공시는 기존처럼 가격 날짜 이하, 뉴스는 생성 시각 이하이므로 휴일/장후 뉴스가 가격보다
   최신일 수 있다. DART는 날짜만 제공하므로 같은 날 공시의 정확한 시간 경계도 미검증이다.
2. `server/service.py`·`store.py` 담당자에게 제안: 감사 manifest에 공급자별 관측/조회 시각,
   캐시 식별자·내용 해시·스냅샷 cutoff를 보존하고, 같은 종목/가격일 재사용과 정보 갱신 정책을
   명시해야 한다. 기존 저장 스냅샷은 자동 재작성하지 않는다. 새 Fact 때문에 신규 내용 해시는 달라진다.
3. 캐시 mtime은 로컬 힌트다. 복사로 mtime이 바뀐 옛 장중 캐시를 판별하지 못하며,
   7일 이상 지난 정상 캐시의 공급자 정정도 자동 탐지하지 않는다. 실제 발표 지연 및
   임시 휴장·특별 거래시간은 거래소 캘린더/발표 상태 확인이 필요하다. 15:40만으로 확정을 보증하지 않는다.
4. 지수 추가 조회는 캐시가 없으면 KRX 일별 요청 지연이 추가된다. 최대 22종목 거래일 구간이며
   400일 전체 지수는 요청하지 않는다. 전향 활성화 전에 지수 캐시 준비와 실제 지연 측정이 필요하다.
5. 기업행사·상장주식수 변동 감지 정책과 보정 데이터 선정은 별도 결정이다. 과거 비교 Fact를
   미래 성과로 읽는 프롬프트/검토기 오류 여부는 해당 담당자가 독립 fixture로 확인해야 한다.
6. 실제 키/모델 접근 및 신규 총비용 상한 승인 후에만 유료 모델 검증을 재개한다.
   RAG 기본 비활성 유지. 배포·전향 스케줄 활성화·push·merge 없음.
