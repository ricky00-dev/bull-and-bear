# 실험 설계: 토론은 단일 에이전트보다 나은가

목표는 **증명이 아니라 측정**이다. 표본이 작아 통계적 유의성은 기대하지 않는다. 전시에서 "이 기간, 이 종목에서
이렇게 나왔다"를 정직하게 보여 주고, 한계를 같이 적는다.

## 질문

1. **토론 vs 단일**: 같은 스냅샷을 받은 단일 에이전트보다, 매수·매도 토론을 거친 중재자 판정이 더 자주 맞는가?
2. **근거 품질**: 토론은 검증기 반려(틀린 수치 인용)를 줄이는가? 중재자가 꼽은 결정적 근거는 어떤 종류인가?
3. **AI vs 사람**: 관람객 판정과 중재자 판정의 적중률 차이 (전시 기간 데이터).

## 설계

| 항목 | 값 |
|---|---|
| 종목 | 고정 10개, 업종 분산 (아래 표). 모두 코스피 → 비교 지수 코스피 |
| 기간 | 11/4(전향 운용 시작) ~ 11/26 매 거래일. 7거래일 채점은 11/13부터 쌓인다 |
| 시각 | 장 마감 뒤 16:40 KST (당일 종가 포함 스냅샷) |
| 조건 A | 토론: 토론자 Haiku 5.5 × 2, 3라운드 + 중재자 Opus 5.5 |
| 조건 B | 단일: Opus 5.5 하나가 **같은 스냅샷**으로 바로 판정 (같은 출력 형식: BUY/HOLD/SELL + 확신도 + 결정적 근거) |
| 채점 | 서비스와 같은 규칙. 3·7거래일 뒤 코스피 대비 초과수익, 보류는 ±2%p 이내면 적중 |
| 주 지표 | 7거래일 적중률 (A vs B) |
| 보조 지표 | 3거래일 적중률, 확신도 보정(확신 높을 때 더 맞는가), 판정 분포(보류 쏠림), 근거 정확도, 토론당 비용·시간 |

## 표본과 한계 (발표 때 그대로 말한다)

- 10종목 × 약 16거래일 ≈ 조건별 160건, 그중 7거래일 채점이 끝나는 건 약 100건. 적중률 ±10%p 안팎의 차이는 우연일 수 있다.
- 같은 날 종목들은 시장 전체 흐름을 같이 탄다 (독립 표본이 아님). 결과는 "이 기간 장세에서"라는 단서를 단다.
- 보류 구간(±2%p)이 넓으면 보류만 외쳐도 적중률이 높다 → **판정 분포와 "항상 보류" 기준선**을 같이 보여 준다.
- 기준선 세 개를 함께 표시: 항상 보류, 항상 매수, 무작위.

## 구현

- 조건 A: Spring 전향 운용 스케줄러 (`bullbear.forward-run`, 구현됨). 사용자도 같은 토론을 재사용한다.
- 조건 B: **워커에 단일 모드 필요** — `POST /debates`에 `mode: "single"` (계약 v0.5 예정, jangwonii).
  Spring은 같은 스냅샷 ID로 단일 판정을 요청하고, 사용자에게는 보여 주지 않고 실험 결과 화면에만 쓴다.
- 결과 화면 (M3): 조건별 적중률 + 기준선 + 표본 수 + 기간. 전시 모드 큰 화면에 같이 띄운다.

## 예산

조건 A ≈ $0.26, 조건 B ≈ $0.05 → 10종목 × $0.31 × 22거래일 ≈ **월 $68**. 전향 운용 하루 상한 $4 (`forward-run.daily-usd`).
